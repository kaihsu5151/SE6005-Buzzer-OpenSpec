# Design

## Context

本專案尚無應用程式或既有能力規格。正式需求見 `docs/期末專題說明.pdf`，活動在同一台電腦以多個瀏覽器頁面示範。已檢視 `docs/軟工期末專案_單題_範例.xlsx` 和 `docs/軟工期末專案_題組_範例.xlsx` 的工作表及儲存格結構：前者有六個單題，答案區為空白的橫向合併格；後者有四個主題號，前兩題各含兩列子題及既有子題標示，後兩題為單題。兩者各有「學習單」工作表，均未包含下述題目標記。這些觀察只適用於本機 Excel 副本，Google Sheets 原表、轉換結果與 API 的合併格及授權行為尚未驗證。

## Goals / Non-Goals

**Goals:** 易於初學者在本機執行；將活動規則集中於伺服器；透過動態映射安全讀寫 Google Sheets，並以測試及人工示範驗證。

**Non-Goals:** 公網部署、正式身分驗證、題組同時作答、CSV、答案正確性判斷及公平順位調整。

## Decisions

### 架構與身分

使用 Flask 與 HTML/CSS/JavaScript，SQLite 儲存活動；瀏覽器每秒輪詢狀態。相對 WebSocket，輪詢較容易實作及除錯；離線或網路延遲可能使畫面延後，後端始終是權威。老師與學生選擇入口，學生選擇組別；伺服器以簽章 session 綁定角色與組別，受限路由以 session 驗證，不信任客戶端傳入的身分。不同分頁通常共用 cookie，故 Demo 應使用不同瀏覽器、獨立瀏覽器設定檔或無痕視窗；README 須說明。這是本機展示的角色隔離，不提供防止使用者自行選擇老師或冒用組別的安全認證。Flask session 簽章金鑰從環境變數取得，不提交版本庫。

### 活動與資料

活動採 `準備中 -> 進行中 -> 已結束`，每次活動關聯試算表 ID。SQLite 表至少包含活動（狀態及來源）、組別、題目（活動、題號、工作表 ID、動態位置與原標記）及提交（活動、題目、組別、答案、順位）；活動與題號、活動與組別名稱、題目與組別、題目與順位各有唯一約束。開始前完成匯入；第一版不提供重開或進行中重新匯入。每次輪詢回傳伺服器階段與經角色及階段篩選的資料；活動結束前不得在任何學生回應中附帶其他組資料。

### 提交與順序

以 SQLite 寫入交易序列化開始、結束與提交：提交在取得寫入鎖後重新檢查活動狀態、身分、題目、非空及該組是否已提交，再在同一交易內決定該題下一順位並寫入。唯一約束是最後防線；競爭失敗回報拒絕或可重試錯誤，不分配順位。提交與結束以交易取得鎖的順序決定接受與否；第一個成功提交即第一名，不依客戶端時鐘，亦不判斷答案正確與否。相對以時間戳排序，交易順序可消除同時間戳的平手。

### Sheets 匯入及寫回

採 Google Sheets API 與本機外部憑證（建議服務帳戶，將講義副本分享給其帳戶），不提交金鑰、憑證、session 秘密或真實資料。接受試算表網址或 ID；掃描工作表內容，不假設題數、題號或位置。第一版暫定要求匯入前由老師逐題在答案格填入 `{{Q1}}` 這類標記，其中數字由講義題號決定；合併答案格使用左上角儲存格。標記應完整占據答案格、每題且只出現一次，題號須唯一但不必連續。系統掃描標記並記錄 spreadsheet ID、穩定 sheet ID、實際行列位置及原標記；無標記或重複標記時拒絕匯入並提示準備步驟，而非猜測或產生部分結果。README 須說明如何在原 Guided Notes 或其供活動使用的副本中準備每一題、核對題數，及匯出寫回該次匯入的同一份試算表。僅靠標記無法偵測被遺漏的整題，因此匯入後須由老師核對題數及題號。

未標記原始範本的自動辨識可透過尋找題號／作答欄標題、逐列配對題號及合併格位置探索，但不同講義可能改變欄位、空白列、標題或格式，題組也可能合併題號；目前沒有足夠證據能無歧義辨識所有輸入。直接匯入未標記範本不在目前已規格化的第一版能力中，不能宣稱已支援。助教測試資料不保證預先標記，格式準備能否在測試時執行尚待向助教確認；若必須直接匯入未標記資料，須先重新設計並修訂規格及驗收。題組及其同時提交功能仍排除，不將題組子題標示視為支援的單題標記；不可靜默忽略未支援題組而宣稱匯入完整。

匯出前重讀所有目標格並確認原標記及位置未改變，若有差異則整次中止；僅對有第一順位的格建立精確寫入清單，以 RAW 文字值及 Sheets batch update 寫入，避免公式解讀及覆蓋其他格。未作答格不納入清單。顯示 API 失敗，成功後記錄已匯出，避免以舊標記重複匯出。讀取與寫入間外部編輯仍可能造成競態：本機 Demo 要求匯出期間不要編輯原表，因 Sheets 不提供本設計所需的跨讀寫條件交易，不宣稱完全防止並行外部修改。若 API 回傳不明確錯誤，提醒老師檢查原表，不盲目重試。

## Risks / Trade-offs

- [未標記講義無法直接匯入] → 明確說明逐題準備標記、核對題數，並向助教確認測試允許此步驟；如不允許，先修訂規格。
- [Google Sheets 行為未驗證] → 用實際 Sheets 副本驗證授權、合併格左上角讀寫及標記格式；本機 Excel 觀察不代表 API 相容。
- [本機角色可被冒用] → 明示僅限受信任本機示範，後端仍強制角色及組別範圍。
- [外部授權與網路失敗] → 明確提示，文件說明設定與排錯；禁止使用假資料替代正式整合驗收。
- [API 跨讀寫競態與不確定結果] → 匯出前驗證、避免同時編輯並人工檢查結果。

## Migration Plan

綠地專案無既有資料遷移；建立本機資料庫並使用講義副本測試。若匯出錯誤，由使用者透過 Google Sheets 版本紀錄還原；部署或操作前保留副本。

## Open Questions

- 確認助教測試是否允許對提供的原始講義先逐題加入標記，以及如何確認未漏題；若不允許，需調整能力規格。
- 確認 Google Sheets 副本的合併格左上角標記與 API 讀寫行為，以及如何可靠識別並拒絕未支援的題組。
- 確認 Google 帳戶可使用服務帳戶授權，及兩小組使用一致的講義格式與功能範圍。
