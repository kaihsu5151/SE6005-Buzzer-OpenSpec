# Spec Delta

## Purpose

讓學生以組別為單位公平提交每題答案，並以伺服器接受有效提交的順序決定各題順位與成功答案，供活動結果查詢。

## ADDED Requirements

### Requirement: 有效組別提交
系統 SHALL 僅在搶答中接受已選組學生對已匯入題目的非空答案，並將答案歸屬於該組。

#### Scenario: 非空答案
- **WHEN** 學生於搶答中為其組別提交存在題目的非空答案
- **THEN** 系統記錄答案並回報提交成功

#### Scenario: 空白答案
- **WHEN** 學生提交空字串或僅含空白字元的答案
- **THEN** 系統拒絕提交且不分配順位

#### Scenario: 活動階段不允許提交
- **WHEN** 學生在活動開始前或結束後提交答案
- **THEN** 系統拒絕提交且不分配順位

### Requirement: 同組同題一次提交
系統 SHALL 每個活動中每組每題最多接受一次提交，且不得修改已接受答案。

#### Scenario: 重複提交
- **WHEN** 同一組再次提交已成功作答的題目
- **THEN** 系統拒絕新提交，原答案與順位保持不變

### Requirement: 各題順位與成功答案
系統 SHALL 對每題獨立依伺服器接受有效提交順序給予唯一且一致的順位，第一順位的答案為搶答成功答案，不判斷答案正確性。

#### Scenario: 兩組同時提交
- **WHEN** 兩組近乎同時有效提交同一題
- **THEN** 系統為其分配不同的第一及第二順位，且所有結果查詢一致

#### Scenario: 題目獨立排序
- **WHEN** 第 1 組最先提交第一題，第 2 組最先提交第二題
- **THEN** 各題的第一順位及成功答案分別屬於對應組別

#### Scenario: 無作答
- **WHEN** 某題在活動結束時沒有有效提交
- **THEN** 結果標示該題無作答且沒有成功答案
