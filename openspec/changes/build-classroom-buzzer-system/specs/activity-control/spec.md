# Spec Delta

## Purpose

讓老師與學生組別在同一本機活動中操作，維持共同的活動階段，並依角色與階段限制可見資訊及可執行的操作。

## ADDED Requirements

### Requirement: 選擇角色與組別
系統 SHALL 提供老師入口與學生組別選擇，支援至少兩個不同學生組別及獨立瀏覽器頁面。

#### Scenario: 多組加入
- **WHEN** 使用者在不同頁面選擇老師、第 1 組及第 2 組
- **THEN** 各頁面以其所選角色及組別操作同一活動

### Requirement: 後端權限檢查
系統 SHALL 依伺服器建立的角色與組別身分檢查每個受限請求，不依賴畫面隱藏或請求自行宣稱的角色與組別。

#### Scenario: 學生嘗試老師操作
- **WHEN** 學生身分直接送出開啟、結束、匯入或匯出請求
- **THEN** 系統拒絕操作且不變更活動或試算表

#### Scenario: 學生冒用其他組別提交
- **WHEN** 學生請求以非其身分所屬組別作答
- **THEN** 系統拒絕該請求且不新增提交

### Requirement: 老師控制活動
系統 SHALL 允許老師在題目匯入後開始搶答及結束進行中的搶答，並在後端拒絕不符合目前階段的操作。

#### Scenario: 開始與結束
- **WHEN** 老師在匯入題目後開始活動，隨後結束活動
- **THEN** 活動依序進入搶答中與已結束階段

#### Scenario: 尚未匯入題目
- **WHEN** 老師在沒有成功匯入題目時嘗試開始活動
- **THEN** 系統拒絕開始並顯示原因

### Requirement: 同步活動階段
系統 SHALL 讓老師及學生頁面每秒向伺服器更新活動階段，並以伺服器狀態決定操作是否有效。

#### Scenario: 開始或結束同步
- **WHEN** 老師開始或結束活動且其他頁面可連線
- **THEN** 各頁面在下一次每秒更新後顯示新的階段

#### Scenario: 舊頁面提交
- **WHEN** 活動已結束但學生頁面尚未更新而送出答案
- **THEN** 伺服器拒絕提交

### Requirement: 依角色與階段限制資訊
系統 SHALL 讓老師查看所有提交資訊；結束前學生僅可取得本組資訊，結束後才可取得所有組別的結果。

#### Scenario: 活動中查詢
- **WHEN** 學生在活動結束前查詢狀態或結果
- **THEN** 回應不包含其他組別的答案、提交狀態或順位

#### Scenario: 活動結束後查詢
- **WHEN** 學生在活動結束後查詢結果
- **THEN** 系統顯示各題所有提交及其順位與成功答案
